# Массовый сброс расхода квоты

Откройте **Пользователи → Действия со списком → Сбросить расход квот всем**.
Панель сначала читает полный список и показывает число учётных записей.
Поиск и фильтры списка не ограничивают действие; оно включает отключённых
пользователей и пользователей без лимита.

Обнуляется только расход квоты Telemt. Сами лимиты, сроки доступа, блокировки,
ссылки, накопленный трафик/графики панели и история IP сохраняются.
Пользователь с исчерпанной квотой снова сможет подключаться, если другие
ограничения не препятствуют доступу. При активных подключениях новый расход
может появиться сразу: ноль не означает остановку учёта.

После явного подтверждения панель обрабатывает пользователей последовательно.
Окно можно закрыть; при возврате к разделу или обновлении страницы прогресс
загружается с панели. Завершённые сбросы отменить нельзя.

## Как читать результат

- **Подтверждено** — Telemt вернул успешный ответ.
- **Отказано** — получен известный отказ до изменения квоты, например пользователь
  уже удалён или конфигурация изменилась.
- **Неизвестно** — результат не подтверждён. При потере ответа или ошибке сервера
  квота уже могла измениться. В частности, Telemt 3.5.5 обнуляет счётчик в памяти
  до записи состояния на диск, поэтому ошибка записи не доказывает отсутствие сброса.
- **Не отправлены** — оставшиеся запросы после остановки операции.

Индикатор показывает обработанные запросы, а не долю успешных сбросов.
Панель останавливает отправку при неоднозначном результате, изменении ревизии,
переходе API в read-only или общей ошибке доступа. Не редактируйте конфигурацию
Telemt параллельно со сбросом; проверка ревизии использует возможности его API
и не заменяет транзакцию на удалённом сервере.

## Повторный запуск и перезапуск панели

Повторный запрос с тем же принятым подтверждением возвращает прежнюю операцию,
пока её запись доступна. Автоматических повторов сброса нет. Для отдельной
учётной записи проверьте её состояние и используйте действие на странице
пользователя; новый массовый запуск снова затронет всех.

Текущий/последний результат хранится в памяти панели, независимо от драйвера
истории. Перезапуск панели прекращает отправку и не возобновляет её автоматически.
Если запись операции потеряна, интерфейс сообщает о недоступном результате,
а не об отмене или успехе. Уже выполненные сбросы не откатываются.

При включённом аудите записываются начало и итог операции с общими счётчиками.
Подробности исключений доступны в окне результата с постраничным просмотром.

## Автоматический сброс

**Пользователи → Действия со списком → Расписание сбросов** открывает общее
расписание. По умолчанию оно выключено. На странице пользователя есть отдельная
вкладка **Автосброс** с тремя режимами: наследовать общее, своё расписание или
отключить. Свои расписания работают независимо от переключателя общего.

Можно выбрать 1, 7, 30 или другое целое число календарных дней и дату/время
первого запуска. 30 дней — интервал, не месяц; ручной сброс не сдвигает эту сетку.
Для запуска первого числа месяца используйте cron `0 0 1 * *`.
Поддерживаются пять полей cron, списки, диапазоны, шаги, названия месяцев и дней
недели; воскресенье — `0`, `7` или `SUN`. Команды, секунды, `@daily` и расширения
`L/W/#` не поддерживаются. Если ограничены одновременно день месяца и день недели,
достаточно совпадения одного из них.

Пояс один для всей панели, по умолчанию серверный. При выборе серверного пояса
сохраняется его текущее значение. Предпросмотр считает бэкенд в этом поясе,
независимо от пояса браузера. При переводе часов несуществующее местное время
пропускается, повторяющееся выполняется один раз. Изменение правила или пояса
назначает будущие запуски: само сохранение не обнуляет квоты.

После недоступности панели или API Telemt выполняется один пропущенный сброс,
не очередь за все пропущенные периоды. Пока идёт ручная операция, автоматическая
ждёт. Сбросы используют тот же последовательный исполнитель и проверку ревизии.

Перед началом панель сохраняет отметку выполнения в техническом файле состояния
в `data_dir`. Без постоянного доступного файла автосброс не запускается, даже
если история работает в памяти. Отдельная база для расписаний не нужна.
При перезапуске уже начатая операция не повторяется, в том числе её оставшиеся
запросы: результат нужно проверить вручную. Неизвестные счётчики не выдаются за нули.
Последний итог доступен на странице общего расписания; при включённом аудите
записываются изменение правил, начало и результат автоматической операции.

Индивидуальные правила привязаны к имени пользователя. Удаление через панель
убирает правило. После удаления/повторного создания учётной записи напрямую
в Telemt проверьте её вкладку «Автосброс»: API не предоставляет неизменяемый ID,
который позволял бы надёжно различить такие учётные записи.
